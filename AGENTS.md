# Правила для автоматизированных изменений

Файл для ИИ-агентов и любых автоматических правок. Люди работают по тем же правилам: они подробно изложены в [CONTRIBUTING.md](CONTRIBUTING.md).

## Перед началом

- Прочитайте `README.md`, `CONTRIBUTING.md`, `docs/architecture.md` и относящиеся к задаче ADR в `docs/adr/` (перечень — `docs/adr/README.md`).
- Проверьте, что уже реализовано. Не описывайте как готовые функции то, что есть только в архитектурном документе или в HTML-прототипе. Функция считается готовой, только когда она работает в программе и покрыта тестами.
- Одно изменение — один результат. Не смешивайте в одном PR рефакторинг, новую функцию и обновление зависимостей.

## Архитектура: что нельзя нарушать

- Слои Clean Architecture и теги Nx (`type:domain`, `type:application`, `type:infrastructure`, `type:feature-ui`, `type:app`) обязательны. Не отключайте `@nx/enforce-module-boundaries`, не добавляйте исключений в его конфигурацию и не обходите его относительными путями между библиотеками.
- Домен (`libs/*/domain`) — чистый TypeScript: без Angular, RxJS, Node, Electron, SQLite, ExcelJS и DOM, без чтения часов и случайных чисел (для этого есть порты `Clock` и `IdGenerator`).
- Слой приложения знает только домен и интерфейсы портов. Реализации портов лежат в инфраструктуре и подключаются в composition root (`apps/ui`, `apps/desktop`).
- Контексты не импортируют домены друг друга. Планирование получает паспорт только через порт `PassportView`, импорт пишет в паспорт только через сценарии паспорта.
- Renderer не обращается к Node. Доступ к диску, SQLite, ExcelJS и печати есть только у main-процесса, через типизированный IPC-контракт из `libs/ipc/contracts`. Входные данные каждого канала проверяются схемой zod в main.
- Доменные нарушения возвращаются как `Result` с текстом для пользователя, а не как исключения.

## Предметные правила

- Координата — пара целых чисел `{км, м}`. Расстояние считается через длины километров направления (`KmLengths`): километр бывает нестандартной длины, поэтому формула `км * 1000 + м` запрещена везде, кроме теста, который проверяет, что она не используется. Дробные километры не хранятся.
- Пикет `p` занимает `[(p − 1)·100; p·100)` м от начала километра. У нестандартного километра пк 1–9 всегда по 100 м, а вся разница относится на пк 10 ([ADR-0005](docs/adr/0005-chainage-km-m.md)).
- ПД определяется по границам подразделений, отмеченных действующими при импорте. Столбец «ПД» в таблицах характеристик по отрезкам содержит устаревшие коды и не используется.
- Строки выгрузок отбираются по периоду действия на дату редакции; «31.12.9999» означает открытый период.
- Ничего не привязывайте к конкретной дистанции: программа работает с любой. Названия станций, направлений, номера ПД и исключения (например, ликвидированные станции) — это данные редакции, а не код.
- Нормативы (периодичность ремонтов, допуски, виды работ и единицы) приходят из шаблона ручных данных и хранятся в базе. Не записывайте их значения в код константами и не подставляйте их из памяти или из интернета. Единственное исключение — файл данных типового перечня видов работ `libs/import/infrastructure/catalogs/typical-work-kinds.json` ([ADR-0032](docs/adr/0032-typical-work-kinds.md)): составитель по желанию дописывает его в выдаваемый шаблон, в паспорт он попадает только после загрузки и подтверждения. Коды его строк не меняются; периодичность, допуски и объёмы в него не добавляются.
- Наименование вида работ — текст для человека, а не ключ. Связи, расчёты и оформление (условное обозначение, пиктограмма, цвет, краткая подпись) не выводятся из наименования разбором текста: только по коду вида или из явных полей ([ADR-0036](docs/adr/0036-typical-catalog-spelling.md)). Неизвестный вид получает нейтральное оформление.
- Год последнего КР главного пути — год последней укладки рельсов на отрезке при любом признаке укладки. Год последнего ремонта, просрочка и потребность в ремонте по каждому отрезку вычисляются и не хранятся.
- Импорт ничего не исправляет молча. Расхождение в данных (станция переезда не совпадает с километром, длина отрезка не сходится с координатами) становится замечанием в отчёте, решение принимает пользователь.

## Данные и конфиденциальность

- Выгрузки ЕК АСУИ, `passport.sqlite`, файлы планов `*.ppr.json`, PDF листов и любые их фрагменты — служебные данные, в некоторых есть ФИО работников. Никогда не добавляйте их в репозиторий, в тесты, в issue, в описание PR и в сообщения коммитов. Рабочие файлы лежат в `private-data/`, папка указана в `.gitignore`.
- Фикстуры для тестов генерирует скрипт из вымышленных направлений, станций и ФИО. Сохраняйте в них особенности настоящих форм: заголовки, нестандартные километры, устаревшие коды ПД, «Нет данных», «-1», «-----».
- ФИО из столбцов «Скорректировал» при импорте не сохраняются.
- Программа не обращается к сети. Не добавляйте телеметрию, автообновление и загрузку шрифтов или скриптов из интернета.

## Совместимость

- Формат файла плана версионируется. Любое изменение формата — новая версия, миграция с предыдущей и тест на файле каждой прежней версии. Файл новой версии старой программой не перезаписывается.
- Миграции SQLite только добавляются: применённую миграцию не меняют. Перед миграцией программа делает резервную копию базы.
- Импорт проекта из HTML-прототипа поддерживается отдельным адаптером. Не ломайте его без замены.

## Проверка и выпуск

- Перед PR выполните `npm run check`. Если что-то не проверено, напишите в описании PR, что именно и почему.
- При изменении расчётов (километраж, доли по ПД, план, просрочка КР), импорта, экспорта или вида листов добавляйте предметные тесты. При изменении вида листов обновляйте эталонные снимки только вместе с объяснением, что изменилось.
- Новые зависимости, которые попадают в программу, — только с разрешительными лицензиями (MIT, BSD, Apache-2.0, ISC, OFL для шрифтов). Укажите лицензию в описании PR.
- Обновляйте `CHANGELOG.md` и документацию, когда меняется поведение для пользователя. Причины архитектурных решений записывайте в `docs/adr/`.
- Ничего не публикуйте и не выпускайте автоматически. Сборка exe и создание релиза запускаются только вручную владельцем репозитория.
