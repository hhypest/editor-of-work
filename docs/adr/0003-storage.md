# ADR-0003. SQLite для паспорта по редакциям, JSON для годового плана

**Статус:** принято · **Дата:** 20.10.2026

## Контекст

Данных два вида с разным циклом жизни. Паспорт дистанции (оргструктура, характеристики пути, станции, переезды, нормативы) меняется редко, но годовой план должен через годы открываться с теми данными, по которым составлен. План меняется постоянно, один файл на дистанцию и год, его копируют и передают как документ.

## Решение

- **`passport.sqlite`** в папке `data` рядом с exe (если папка недоступна для записи — `%LOCALAPPDATA%\editor-of-work`). Одна база — одна дистанция.
- Паспорт хранится **редакциями**: черновик → действует → архив. Действует ровно одна; действующая и архивные неизменяемы, правка — новый черновик копией строк.
- Миграции схемы — пронумерованные SQL, только вперёд. Перед миграцией и вводом редакции в действие — резервная копия через backup API. WAL, внешние ключи, транзакции; запросы — Kysely.
- **`*.ppr.json`** — файл годового плана: версия формата, ссылка на редакцию и **снимок её данных**, сам план. Чтение — через цепочку миграций и схему zod; запись атомарная (временный файл → переименование, `.bak`), автосохранение.

## Последствия

- План открывается на любом ПК и не зависит от того, что потом стало с базой.
- Переход плана на новую редакцию — явное действие с отчётом об изменениях (работы сменили ПД, исчезли пути и стрелки).
- Вычисляемые величины (просрочка КР, потребность в ремонте, доли по ПД) не хранятся.

## Рассмотренные варианты

- **Всё в SQLite** — план нельзя просто передать файлом.
- **Всё в JSON** — справочник в несколько тысяч строк с редакциями и сравнением неудобно вести без запросов и транзакций.
