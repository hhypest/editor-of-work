# ADR-0008. Служебные данные не попадают в репозиторий

**Статус:** принято · **Дата:** 20.10.2026

## Контекст

Репозиторий публичный. Выгрузки ЕК АСУИ, база паспорта, годовые планы и PDF листов — служебные материалы ОАО «РЖД»; в выгрузках есть ФИО работников (столбец «Скорректировал»).

## Решение

- Выгрузки, `passport.sqlite`, `*.ppr.json`, PDF листов и их фрагменты в Git не добавляются — ни в код, ни в тесты, ни в issue, ни в снимки экрана. Рабочие файлы разработчика лежат в `private-data/` (в `.gitignore`).
- Проверка `check:public` в CI отклоняет отслеживаемые xls, xlsx, sqlite, файлы планов, pdf и архивы.
- Фикстуры импорта генерирует скрипт из вымышленных направлений, станций и ФИО с теми же заголовками и особенностями настоящих форм.
- ФИО из столбцов «Скорректировал» при импорте не сохраняются.
- Программа не обращается к сети: нет телеметрии, автообновления и загрузки внешних ресурсов.

## Последствия

- Тесты воспроизводимы на любом компьютере без доступа к служебным данным.
- Сверка с реальными выгрузками (например, итоги административного деления) делается локально на эталонах из `private-data/`.

## Рассмотренные варианты

- **Обезличенные копии реальных выгрузок** — риск пропустить поле при обезличивании; генератор надёжнее.
