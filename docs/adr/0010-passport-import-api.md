# ADR-0010. Опубликованный API записи импорта паспорта

**Статус:** принято · **Дата:** 21.10.2026

## Контекст

Импорт должен записывать оргструктуру через сценарий Паспорта (ADR-0006),
не получая его доменные объекты. Существующая библиотека `passport/application`
зависит от `passport/domain` для редакций. Правила Nx запрещают такую транзитивную
зависимость другому контексту. Ослабление границ ради нового сценария недопустимо.

## Решение

Опубликованный порт `PassportOrgImport` и его нормализованные команды выделены
в `libs/passport/import-api` с тегами `type:application`, `scope:passport`.
Библиотека зависит только от общего ядра (`Result`). Ошибка сценария — собственный
DTO, структурно совместимый с ошибкой хранилища, без экспорта доменных типов.
Импорт зависит от этого API; инфраструктура Паспорта реализует его вместе с
существующим `PassportStore`. Правила Nx остаются прежними.

Пакет из четырёх форм заменяется целиком в одной транзакции. Это явная команда,
которая в будущем мастере выполняется после предпросмотра и подтверждения.
Она поддерживает части форм и смену номеров файлов выгрузки. Остальные разделы,
характеристики станций и путей сохраняются; зависимые справочные записи не
удаляются вместе с привязками. Противоречащие ограничениям SQLite координаты
отклоняются без исправления. Отчёт и данные фиксируются совместно.

## Последствия

Граница контекстов проверяется без исключений линтера. Появляется отдельная
небольшая библиотека приложения. Для частичного обновления одной формы потребуется
отдельный сценарий с правилами сверки зависимостей; текущий API требует весь пакет.
Мастер и IPC выбора файлов остаются задачей #21.

## Рассмотренные варианты

- Импорт из `passport/application` — раскрывает транзитивную зависимость от домена.
- Разрешить домен Паспорта Импорту в ESLint — нарушает ADR-0001 и AGENTS.md.
- Записывать SQLite из Импорта — нарушает владение данными Паспорта.
