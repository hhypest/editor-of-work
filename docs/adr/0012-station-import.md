# ADR-0012. Станционные формы и исключения редакции

**Статус:** принято · **Дата:** 21.10.2026

## Контекст

Ветка `feat/station-import` содержит разбор осей, BEx-экспликаций, трёх книг
переездов и ОКАТО. Для использования в паспорте нужны запись, повторный импорт,
журнал и явный список исключений. Начальная SQL-схема требует границы у каждой
оси и ровно один главный путь у переезда. В выгрузке есть остановочные пункты
без границ, переезды на станционных/подъездных путях и направления с несколькими
главными путями. Подстановка оси вместо границ или выбор последнего пути скрывает
неизвестность и меняет данные без решения составителя.

## Решение

Расширить опубликованный API ADR-0010 портом `PassportStationImport`.
Полный пакет семи форм пишется только в черновик вместе с журналом. Он может
содержать несколько частей одной формы и несколько форм в одной книге.
Предпросмотр использует дату, направления с длинами км, идентичности станций
и путей и список исключений. Токен этой основы повторно проверяется до записи.
Домен Паспорта не раскрывается Импорту, зависимости Nx не ослабляются.

Ключи общих справочников сохраняются при обогащении и повторном импорте,
включая привязки к ПД и ручные раскладки. Прежние импортированные характеристики
путей и стрелок заменяются, ручные поля вне импорта сохраняются. Текст указания
пути у стрелки остаётся текстом; ручной FK не заменяется предположением.

Миграция 005 переносит оси и переезды в таблицы с допускающими отсутствие
границами и привязками, добавляет проверенные `details` и восстанавливает триггеры.
`crossing_line` хранит все совпавшие главные пути направления. Старые строки и
однозначные привязки сохраняются, перед миграцией создаётся backup.
`stationData` читает новые типизированные записи; прежние строки без `details`
остаются в исходных таблицах. Сырые ячейки и ФИО корректировщика не записываются.

Неверная станция в названии переезда — замечание, название не исправляется и не
становится FK. Без распознанной привязки координата остаётся null. Номер переезда
не используется как ключ сведения книг: они соединяются по полному названию,
дубликаты не сводятся молча. Цикл или отсутствующий родитель ОКАТО отклоняет пакет.

Исключения — явная команда с причиной на редакцию. Список хранится по ID станции,
копируется с редакцией и сразу фильтрует представление данных. Повторный импорт
применяет его к осям и экспликациям и обновляет отчёт. Кандидаты на исключение
не применяются автоматически. Само исключение не удаляет общие справочники.

## Последствия

Данные доступны программно для дальнейших расчётов и интерфейса #21.
В SQL появляются nullable границы и многозначная связь переезда, поэтому
потребитель обязан учитывать неизвестность. Сохранение семи форм является
одним результатом, UI, IPC, шаблон ручных данных и расчёт ремонтов остаются
отдельными задачами. Новых зависимостей нет.

## Рассмотренные варианты

- Подставлять координаты оси как границы — вымышленные данные.
- Выбирать один из путей направления — потеря связи с другими путями.
- Удалять общий справочник вместе с выгрузкой — потеря ручных полей и связей.
- Исключать станции без экспликаций автоматически — неподтверждённое решение.
