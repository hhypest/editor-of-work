# ADR-0016. Пошаговый импорт и проверка редакции при подтверждении

**Статус:** принято · **Дата:** 22.10.2026

## Контекст

Три существующих сценария атомарно записывают пакеты оргструктуры, характеристик
и станционных форм. Для #21 нужен интерфейс, который использует эти сценарии,
показывает замечания и требует подтверждения. Оргструктуру необходимо принять до
характеристик и станций, так как она создаёт направления. Время между предпросмотром
и записью допускает другой импорт или ручное изменение черновика.

## Решение

Мастер состоит из трёх шагов 4/6/7 форм. Каждый шаг — отдельный пакет и транзакция;
ранее принятые пакеты сохраняются при ошибке следующего. Составитель явно выбирает
действующие ПЧУ/ПД; предложения проверки не отмечаются автоматически. Кандидаты на
исключение станций остаются только подсказками.

Разбор инфраструктуры отделён от записи: `readOrgExports`, `prepareOrgExports`,
`prepareSegmentExports`, `prepareStationExports` не изменяют паспорт. Прежние
`import*Exports` сохранены как совместимые обёртки подготовки и записи.

Порт `ExportWizardClient` находится в Import application. Composition root
подключает UI к типизированному каналу `import:exports` с проверкой zod. Пути
выбирает системный диалог main; для frameset realpath связанной части должен
оставаться внутри реальной папки выбранного файла. Нельзя выйти через `..`,
абсолютный адрес, другую схему или символическую ссылку. Лимиты 1000 частей и
64 МиБ на файл ограничивают технический объём обработки.

Сеанс хранит исходные данные и подготовленную команду только в main. Renderer
получает выбор подразделений или сводку строк и замечания, но не исходные таблицы
и не команду записи. Один сеанс на процесс, срок 10 минут, одноразовый токен
связан с редакцией. Подтверждение не перечитывает файл с диска.

В команды OrgImport/SegmentImport/StationImport добавлено необязательное поле
`expectedEditionToken`: SHA-256 согласованной проекции EditionData. Мастер всегда
передаёт его. Все три сценария проверяют токен внутри той же транзакции, где
происходит замена данных и журнала. Отказ не оставляет частично записанного пакета.
Прежние проверки basisToken, даты, статуса и ссылок сохраняются. Для существующих
программных вызовов поле необязательно; renderer не может прислать свою команду.
Токен вычисляемый и в БД не хранится; схема и миграции не меняются.

## Последствия

Последовательность трёх шагов видна пользователю. При ошибке можно повторить один
пакет; повторная загрузка характеристики не требует заново принимать оргструктуру.
Предпросмотр показывает объём замены и замечания, а не точную разницу каждой строки.
После изменения редакции необходима новая подготовка. Доступ к реальным данным
для приёмки остаётся локальным; CI использует генератор вымышленных форм.

## Рассмотренные варианты

- Записывать все 17 форм сразу — требует нового общего транзакционного сценария
  с предварительной виртуальной основой направлений и более сложным откатом.
- Проверять редакцию только в IPC до вызова записи — оставляет окно гонки.
- Вызывать существующие `import*Exports` при выборе файлов — записывает до согласия.
