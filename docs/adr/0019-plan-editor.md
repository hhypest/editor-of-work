# ADR-0019: История редактора плана в main и типизированные команды

**Статус:** Принято

**Дата:** 2026-10-22

## Контекст

Годовой файл уже открыт в main: там находятся путь, атомарная запись и автокопия. Renderer не может декодировать файл адаптером с Node/crypto и не должен держать независимую изменяемую версию плана. Нужны редактор работ, понятные ошибки поля, сохранение и отмена без потери данных.

## Решение

История `PlanSession` хранится рядом с текущим планом в main. Сценарии слоя приложения `changeEditor`, `editorView` и `inspectEditorPlace` вызывают существующие доменные команды, `planRows` и правила долей. UI работает с DTO и отправляет типизированные действия через новое действие `editor` существующего канала `plan:file`; запрос и ответ проверяются zod. Нового формата файла нет.

Каждое изменение содержит ожидаемую ревизию. Устаревшая команда отклоняется до записи; чтение состояния позволяет явно обновить редактор. Новая история, представление и кодированный файл проверяются до смены текущего документа. Ошибки, отмена диалога и неудачная запись сохраняют прежние документ и путь. Сохранение текущего плана удерживает историю и запоминает сохранённый снимок: отмена/повтор корректно меняют признак несохранённых правок.

Синтаксическая подсказка места возвращает нормализованный текст, метры и ошибки с диапазоном символов. UI игнорирует запоздавший ответ. Применение работы выполняет полную доменную проверку. Пакет ручных значений таблиц проверяется целиком и фиксируется одним шагом истории. Строковые числовые поля различают пустое значение и ноль, допускают десятичную запятую, отклоняют мусор и отрицательные значения.

Фасад renderer на signals живёт до закрытия приложения, поэтому переход между разделами не удаляет незавершённый ввод. Ctrl+S сначала применяет ввод; ошибки останавливают запись. Нативная отмена в текстовом поле сохраняется. Замена документа и закрытие окна требуют явного решения при несохранённых данных. Найденная автокопия не перезаписывается, пока пользователь не восстановит её или не откажется от неё.

## Последствия

Первый шаг #24 независим от PR #71 и направляется в main. Работы, ручной план, потребность и гриф доступны по существующему срезу и формату. Создание нового плана из базы, дополнительные показатели, подрядные / ИССО / ЗП, настройки и привязка к текущему листу остаются в #24. Перерисовка листа менее 200 мс не объявляется проверенной. PDF и Ctrl+P для экспорта подключаются в #25; пока сочетание показывает статус недоступности вместо печати интерфейса.

## Рассмотренные варианты

- Независимые планы в renderer и main: сложнее обеспечить одну историю, путь и автокопию.
- Передавать заново весь JSON при каждой правке: скрывает смысл команды и затрудняет отклонение устаревших изменений.
- Сброс истории при сохранении: лишает пользователя ожидаемой отмены только что сохранённой правки.
