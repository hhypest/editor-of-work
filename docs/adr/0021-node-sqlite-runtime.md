# ADR-0021: Встроенный node:sqlite и проверка production-рантайма

**Статус:** Принято

**Дата:** 2026-10-22

## Контекст

Аудит `aceb0e1` выявил расхождение: хранилище #13 использует встроенный node:sqlite и адаптер Kysely, а §3/§12 архитектуры описывали better-sqlite3 и electron-rebuild. ADR-0002 оставлял оба варианта открытыми. Сборка TypeScript и тесты под системным Node не доказывают наличие нужного API в Node, встроенном в Electron.

## Решение

Подтверждаем реализованный вариант: node:sqlite, DatabaseSync и backup, Kysely через локальный sqlite-dialect. better-sqlite3 не является зависимостью программы; electron-rebuild для него не нужен. Это уточнение выбора в ADR-0002, а не смена хранилища или миграция базы. SQLite и JSON плана из ADR-0003 сохраняются.

CI использует Node из .nvmrc на Ubuntu и Windows. До закрытия #6 и выпуска нужна проверка настоящего Electron Windows: версия встроенного Node, импорт node:sqlite, создание временной базы, backup и повторное чтение. Portable-сборка и приёмка запускаются владельцем вручную. Успех npm run check не помечает эти проверки выполненными.

Текущий диапазон engines этим ADR не меняется. Поддержку Node 22 следует подтвердить отдельной матрицей либо сузить диапазон после проверки требований Angular/Electron и инструментов. Отсутствие такой матрицы зафиксировано как открытая проверка.

## Последствия

Не добавляем нативную зависимость и пересборку, руководствуясь устаревшим текстом. До проверки Electron остаётся риск несовпадения API встроенного и системного Node; он блокирует выпуск, а не скрывается успешной компиляцией. Новые зависимости и изменения схемы БД не нужны.
