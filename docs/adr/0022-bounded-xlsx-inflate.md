# ADR-0022. Бюджет распаковки xlsx

**Статус:** принято · **Дата:** 22.10.2026

## Контекст

Независимый аудит, пункт 2.3, подтвердил: отбор нужных частей в читателе
[ADR-0009](0009-xlsx-reader.md) не ограничивал распакованный объём. Небольшой ZIP
может содержать огромный XML. Проверка только размера файла на диске этого
не предотвращает. Размеры ZIP также могут быть поддельными: прежний `unzipSync`
выделял буфер по заголовку, а заниженный размер мог дать обрезанное содержимое.

## Решение

Внутренний `XlsxArchive` инфраструктуры импорта использует существующий fflate
(MIT). Каталог ZIP читается с фильтром, запрещающим распаковку всех частей.
Он ограничивает число частей и отвергает повтор имени. Перед каждым проходом
проверяются заявленные размеры выбранных частей. Сами части читаются через
потоковый `Unzip` / `UnzipInflate` порциями **1024 сжатых байта**, поэтому даже
ложный размер не позволяет одному вызову распаковать всю большую часть.

Бюджет считает **фактические байты**, проверяется до сохранения каждого выходного
блока и общий для описания книги, общих строк, стилей и выбранных листов.
Фактический размер сверяется с каталогом; локальный заголовок, когда содержит
размер, также должен ему соответствовать. ZIP с data descriptor поддерживается:
его вывод проверяется независимо от отсутствующего локального размера.
Готовый буфер собирается только после проверки части целиком.

Ограничения одной книги:

| Ресурс                             | Лимит   |
| ---------------------------------- | ------- |
| Сжатый ввод читателя               | 64 МиБ  |
| Одна выбранная распакованная часть | 32 МиБ  |
| Все выбранные части обоих проходов | 128 МиБ |
| Все записи каталога ZIP            | 4096    |

Скрытые служебные листы по умолчанию не распаковываются и не расходуют бюджет
XML. Чтение ручного шаблона включает скрытый лист и учитывает его. Ограничения
ресурсов не являются нормативами предметной области. Ошибка возвращается через
существующий `Result` до предпросмотра/записи; данные и журнал паспорта сохраняются.

## Последствия

Формат шаблона, распознавание форм, схема SQLite и файл плана не меняются.
Более крупную книгу нужно повторно выгрузить частями с сохранением комплектности
пакета. Два прохода по сжатому вводу сохраняются; XML по-прежнему разбирается
существующим читателем. Тесты включают сжатый повторяющийся текст, ложные размеры,
data descriptor, скрытые части, общий бюджет и сохранность временной SQLite.

Этот шаг не расширяет поддержку XML (CDATA, пространства имён и атрибуты `si`),
не добавляет проверку CRC и не ограничивает суммарную память объектов разобранных
ячеек точным числом байтов. Ограничение дискового чтения ручного шаблона остаётся
отдельным шагом: лимит читателя применяется к уже полученному массиву.

## Рассмотренные варианты

- Проверять только сжатый размер: степень сжатия этим не ограничена.
- Проверить заголовок и оставить `unzipSync`: не обнаруживает фактический выход
  сверх ложного размера надёжным способом.
- Распаковать целиком и затем измерить: выделение большого буфера уже произошло.
- Сменить библиотеку и XML-парсер вместе: расширяет объём исправления; текущая
  зависимость уже предоставляет необходимую потоковую распаковку.
