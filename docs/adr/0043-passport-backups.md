# ADR-0043: Резервные копии базы паспорта: список, восстановление, предел

**Статус:** Принято

**Дата:** 2026-10-28

Продолжает [ADR-0003](0003-storage.md) и [ADR-0021](0021-node-sqlite-runtime.md); часть #38.

## Контекст

Перед миграцией схемы и вводом редакции в действие программа делает копию базы через SQLite backup API в папку `backups` рядом с базой. Копии копились без предела, а вернуться к ним можно было только вручную, подменив файл при закрытой программе. Составитель работает без администратора и без поддержки; ошибочно введённая редакция или неудачный импорт должны откатываться из интерфейса. База часто лежит на флешке рядом с exe, поэтому место ограничено.

## Решение

- Порт `PassportBackups` слоя приложения: `backups()` и `restoreBackup(id)`. Идентификатор — имя файла копии; renderer путь не задаёт, main ищет только в своей папке `backups` и только имена своего формата `passport-<повод>-<время>-<uuid>.sqlite`.
- Список открывает каждую копию только для чтения: редакции (номер, дата, название, статус) и проверка истории миграций. Копия новой программы или не база паспорта не восстанавливается, причина показывается в списке.
- Перед восстановлением копия проходит `PRAGMA integrity_check`: список читает только редакции, а повреждение других таблиц видно лишь полной проверкой. Непрошедшая копия не подменяет базу.
- Восстановление идёт в общей очереди операций базы. Сначала текущая база копируется с поводом `restore`, затем копия кладётся рядом как `passport.sqlite.restoring`, соединение закрывается, файл переименовывается поверх базы и открывается с обычными миграциями (при более старой схеме — с копией `migration`). Ошибка после закрытия возвращает прежнюю базу из только что созданной копии.
- После каждой новой копии остаются `MAX_PASSPORT_BACKUPS = 10` последних по времени из имени. Только что созданная копия и копия, которую восстанавливают, не удаляются; чужие файлы в папке не трогаются. Ошибка очистки не срывает операцию, ради которой сделана копия.
- Канал `passport:editions` получает действия `backups` и `restoreBackup`; ответ `ok` несёт редакции и, для `backups`, список копий. Отдельный канал не нужен: восстановление меняет те же редакции.
- Интерфейс — раздел «Резервные копии базы» на странице паспорта; список загружается только по запросу, восстановление — после подтверждения с объяснением последствий.

## Последствия

- Ошибочный ввод редакции или импорт откатывается из программы; откат сам обратим через копию `restore`.
- Файлы планов не затрагиваются: они хранят срез редакции; план, созданный после копии, остаётся рабочим.
- Предел 10 копий: долгая серия вводов редакций вытесняет старые копии. Нужная копия переносится вручную из папки `backups`.
- После восстановления номер редакции может указывать на другую редакцию: старая база несёт свой счётчик. Редактор плана перечитывает список редакций при каждом возврате в раздел и без свежего списка план из редакции не создаёт.
- Восстановление закрывает соединение на время подмены файла; предпросмотры импорта, подготовленные до него, отклоняются проверкой токена редакции.
