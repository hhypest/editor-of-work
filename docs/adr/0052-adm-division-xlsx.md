# ADR-0052: Административное деление — книга xlsx с формулами

**Статус:** Принято

**Дата:** 2026-11-02

Задача #32: книга с листами «Адм. деление», «Станции», «Границы ПД», «Справочник», «Пути (исх.)», «Стрелки (исх.)»; итоги формулами Excel 2007; печать главного листа на один лист A4 альбом.

## Контекст

Структура книги согласована по образцу, который прислал пользователь (служебный файл, в репозиторий не добавлен). Итоги образца считаются формулами: SUMIFS, COUNTIFS, COUNTIF, INDEX/MATCH. Длина участка ПД в образце считалась формулой «км × 1000 + м», что неверно для нестандартных километров и запрещено правилами проекта (ADR-0005).

## Решение

- **Модель книги в слое приложения.** `buildAdmDivision` строит модель книги — листы, ячейки, формулы с результатами, оформление, объединения, закрепление, печать — и итоги по каждому ПД и по дистанции. ExcelJS о предмете ничего не знает: адаптер `SpreadsheetExporter` в main только записывает модель.
- **Итоги дважды.** Каждая формула пишется вместе с результатом, посчитанным приложением по тем же правилам: станции сравниваются без учёта регистра, главный путь станции — назначение «главный», станционные пути — все остальные по полной длине. Excel пересчитывает книгу при открытии (`fullCalcOnLoad`); тест вычисляет каждую формулу модели независимым вычислителем и сравнивает с результатом приложения.
- **Длина участка ПД — значение, а не формула.** Программа считает её по координатам и длинам километров направления; расхождение с длиной из выгрузки границ — замечание. Формул «км × 1000 + м» в книге нет.
- **Станции.** Одна строка на станцию, привязанную к действующему ПД; при привязке к нескольким ПД итоги идут по первому коду, остальные — в примечании и в замечаниях. Станции, которые есть в путях или стрелках, но не привязаны к ПД, перечислены под итогами листа «Станции» и в примечании главного листа и в итоги не входят.
- **Руководители** — с листа «Руководители» шаблона ручных данных (ADR-0051) на дату редакции; в главном листе они подставляются формулой INDEX/MATCH из «Справочника», ПЧУ строки станции и границы — `T(INDEX(…))`, чтобы ПД без ПЧУ давал пустую ячейку, а не 0.
- **Канал `documents:xlsx`.** Renderer передаёт модель книги, main проверяет её схемой zod и пишет файл атомарно по пути из диалога. Схема разрешает только функции SUM, SUMIFS, COUNTIFS, COUNTIF, INDEX, MATCH, CHAR, T, отвергает ссылки на другие книги, повтор имён листов и книги больше 500 000 ячеек.
- **Печать.** A4; главный лист — альбом на одну страницу, «Станции» и «Границы ПД» — альбом по ширине, исходные листы — книжная по ширине.

## Последствия

- Книга строится по любой редакции паспорта и не зависит от годового плана.
- Сверка с образцом: по исходным данным образца программа даёт те же итоги по всем ПД и по дистанции; книга, пересчитанная LibreOffice, совпадает с итогами приложения во всех формулах. Сверка выполняется локально на служебном файле и в репозиторий не попадает.

## Рассмотренные варианты

- **Только значения без формул.** Проще, но требование задачи — итоги формулами, чтобы составитель мог поправить исходные листы и получить пересчёт.
- **Формулы без результатов.** Excel всё равно пересчитает, но программы просмотра без пересчёта показали бы пустые итоги, а тест не смог бы сравнить формулы с расчётом приложения.
- **Книга целиком в main.** Main должен был бы повторить сборку среза паспорта; модель из renderer с проверкой схемы повторяет путь PDF (ADR-0050).
