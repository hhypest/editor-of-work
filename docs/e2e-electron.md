# Сквозной сценарий в собранной программе

`npm run test:e2e` проходит путь составителя в production-сборке Electron на вымышленных данных (часть #37, критерии выпуска [0.5.0](releases/0.5.0.md)). Перед запуском выполните `npm ci` и `npm run build`: сценарий запускает собранные `dist/apps/desktop` и `dist/apps/ui`. На Windows команда запускается непосредственно; на Linux нужен графический сеанс либо `xvfb-run -a npm run test:e2e`. В CI сценарий идёт на Windows после `check:electron`.

## Что проверяется

Шаги идут по порядку и останавливаются на первой ошибке. В скобках — пункт приёмки на рабочем ПК, который шаг повторяет на вымышленном комплекте.

| Шаг                                                                                       | Пункт приёмки |
| ----------------------------------------------------------------------------------------- | ------------- |
| Шапка показывает версию из `package.json` и формат плана                                  | 1             |
| Черновик паспорта в новой базе                                                            | 2             |
| Импорт 17 вымышленных форм по трём шагам мастера с выбором подразделений и подтверждением | 3             |
| Шаблон ручных данных с типовым перечнем: выдача, заполнение нестандартных км, загрузка    | 4             |
| Ввод редакции в действие и создание плана на следующий год                                | 5             |
| Ошибка места у поля, исправление и добавление работы                                      | 6             |
| Отмена и повтор                                                                           | 7             |
| Сохранение, повторное открытие, версия программы в файле                                  | 8             |
| PDF текущего листа ПД, всех ПД в один файл и по файлам: А3 альбом, встроенные шрифты      | 9, 10         |
| Файл плана более новой версии не открывается и не перезаписывается                        | 11            |
| Аварийное завершение после минутной автокопии, восстановление, сохранение и копия `.bak`  | 8, 12         |

Книгу ручных данных заполняет вспомогательный скрипт `scripts/e2e/fill-manual-template.ts` так же, как составитель в Excel: дописывает длины нестандартных километров вымышленных направлений на лист «Нестандартные километры». Остальные листы не меняются.

## Как устроен запуск

- Собранные папки копируются во временный каталог; там же создаются база паспорта, `LOCALAPPDATA`, вымышленные выгрузки (`scripts/fixtures.mjs`), книги и планы. После сценария каталог удаляется, в том числе при ошибке.
- Playwright запускает Electron из lock-файла с папкой приложения, как установленная программа запускает `resources/app`. Переменные `ELECTRON_RUN_AS_NODE`, `NODE_OPTIONS` и адрес сервера разработки сбрасываются.
- Подменяются только системные диалоги main (`dialog.showOpenDialog` и `dialog.showSaveDialog`): сценарий заранее кладёт в очередь выбранные пути. Тестовых ветвей в production-коде нет; renderer, preload, IPC, SQLite и печать работают как у составителя.
- Сетевых обращений нет: все данные создаются на месте.

## Результат

После успеха `test-results/e2e/report.json` содержит версию продукта, платформу, имена шагов и их длительность. При ошибке рядом сохраняется `failure.png` — снимок окна на вымышленных данных — и в вывод попадают тексты сообщений программы. В CI папка загружается как артефакт `e2e-windows`.

Для разбора падения задайте `EOW_E2E_KEEP=1`: временный каталог с базой, книгами и планами не удаляется, его путь печатается в конце.

## Чего сценарий не проверяет

- Переносной exe и папку `data` рядом с ним (#6): запускается собранная папка, а не упакованная программа.
- Совпадение листов с эталонами и PDF прототипа (#26): проверяются формат страниц и встроенные шрифты, а не изображение.
- Реальные выгрузки и производительность на рабочем ПК: пункты 13–15 приёмки.
- Шаг автокопии ждёт настоящую минутную запись, поэтому весь сценарий идёт около полутора минут.
