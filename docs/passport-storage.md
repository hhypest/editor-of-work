# Хранение паспорта — задача #13

Планируемый результат: паспорт хранится в SQLite по редакциям. Можно создать
черновик, ввести его в действие и получить архив предыдущей редакции.
После первого ввода действует ровно одна редакция. Данные действующей и архивной
редакций нельзя изменять; правка выполняется в новом черновике.

База создаётся в `data` рядом с программой; при недоступности папки — в
`%LOCALAPPDATA%/editor-of-work`. Перед миграцией существующей базы и вводом
редакции создаётся резервная копия через SQLite backup API. Миграции SQL
нумеруются и применяются только вперёд; контрольные суммы выявляют изменение
уже применённой миграции. Включены WAL и внешние ключи.

Реализация использует встроенный `node:sqlite`, предусмотренный ADR-0002,
и Kysely 0.29.7 (MIT) для типизированных запросов. В Electron 44.9.0 проверены
наличие `DatabaseSync` и функции `backup`; отдельный нативный модуль не нужен.

Проверка: временные базы, повторное открытие, отказ при новой версии схемы,
сбой миграции с откатом, копия до ввода редакции, неизменяемость активных и
архивных строк, переключение редакций одной транзакцией, резервный путь.
Данные тестов полностью вымышленные. Интерфейс редактирования паспорта и
импорт его таблиц относятся к следующим задачам дорожной карты.
