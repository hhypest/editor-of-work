# import-infrastructure

`@eow/import/infrastructure` · контекст «Импорт выгрузок (антикоррупционный слой)» · теги `type:infrastructure`, `scope:import`

Инфраструктура: реализации портов (адаптеры). Не импортирует UI.

`importPrototype` принимает JSON, сохранённый HTML-прототипом, ссылку на редакцию
и генератор идентификаторов. Каталог видов берётся из JSON; для старого файла
без каталога его нужно передать отдельно из прототипа или редакции паспорта.
Встроенных нормативов нет. Внутренние идентификаторы видов остаются ключами плана.

Разбор возвращает опубликованный `PrototypeTransfer` слоя приложения Импорта,
без зависимости от домена Планирования. Composition root main передаёт его в
`buildImportedPlan`: фабрики Планирования проверяют все ссылки и инварианты.
Текущий документ заменяется только после успешной проверки всего проекта.

Импорт не исполняет HTML и не читает часы. Ошибка поля, координаты, ссылки или
работы отклоняет весь проект; ни одна работа не отбрасывается молча. Раскладка
станции переносится в типизированный `legacyLayout` среза и также сохраняется
без изменений в снимке исходного JSON. Редактор и отрисовка относятся к #29;
прочие неподдержанные поля перечислены в отчёте и тоже остаются в снимке.
Подробности и ограничения — [docs/prototype-import.md](../../../docs/prototype-import.md).

## Чтение выгрузок паспорта

`PassportExportSource` реализует порт `ExportSource` слоя приложения Импорта. Тип файла
определяется по содержимому, а не по расширению: xlsx, «веб-страничный» xls (HTML),
frameset с папкой `.files` (через `sibling`) или двоичный xls (ошибка с просьбой пересохранить).
С каждого видимого листа берётся таблица, форма узнаётся по набору заголовков
(`recognizeForm`). У отчётов BEx шапка собирается по уровням над строкой номеров столбцов:
«Граница / От», «Шпалы / Наличие, шт. / ЖБ». Повторный заголовок получает номер:
«Предприятие (2)». Значения не меняются; приводить их к числам и датам помогают
`numberAt`, `dateAt` и `textAt`, а их ошибки указывают файл, лист, строку и столбец.

xlsx читается своим модулем на fflate ([ADR-0009](../../../docs/adr/0009-xlsx-reader.md)).

## Оргструктура

Разбор форм и привязка живут в слое приложения Импорта (`org-forms.ts`, `org-structure.ts`):
`parseSubdivisions`, `parseBoundaries`, `parseStationPd`, `parseTrackPd`, затем
`subdivisionChoices` для мастера и `buildOrgStructure` по отмеченным кодам. Особенности
настоящих выгрузок: у части подразделений пуст столбец «Подразделение» (код берётся
из «Тип+номер»), вышестоящий ПЧУ записан как «предприятие, ПЧУ-01» с ведущим нулём,
у прежних ПД нет границ на дату редакции. Запись результата в черновик редакции
паспорта выполняет `importOrgExports` через опубликованный `PassportOrgImport`.

## Характеристики по отрезкам

`parseSegments` разбирает шесть форм характеристик в записи `ParsedSegment`; столбцы
«ПД» (прежние коды) и «Скорректировал» (ФИО) не читаются. `checkKmLengths` сверяет
заявленные длины с координатами по всем формам сразу (результат — `Result`): каждый отрезок — уравнение
«сумма отклонений длин его километров = заявленная − вычисленная». Сначала решается
то, что следует однозначно, затем самые короткие сходящиеся отрезки считаются
стандартными. Так находятся пары «короткий + длинный км», которые гасят друг друга
на длинном отрезке. Результат — кандидаты в нестандартные км с числом подтверждающих
отрезков; их вводит пользователь. Принятые длины передаются через `KmLengths`;
противоречащие предложения не выбираются по порядку файлов. Границы подразделений (#16) с «Длиной участка, м» передаются в ту же сверку. В рельсах бесстыковой путь записан «б.п.» или «б/с», подъездные пути из формы шпал
пропускаются. Отсутствующая длина границы `-1` не участвует в сверке.
Диапазон строки свыше 100 000 км возвращает `invalid-import` до обхода км и
создания массивов; это технический предел, а не норматив длины направления.

`importSegmentExports` передаёт выбранные формы в `PassportSegmentImport`: данные
и отчёт записываются одной транзакцией только в черновик, с проверкой актуальности
основы сверки. Можно заменить одну форму или несколько, передав все их части;
остальные формы и ручные строки сохраняются. Диапазоны и стороны хранятся без
сведения к одному числу. Подробнее — [хранилище паспорта](../../../docs/passport-storage.md#характеристики-по-отрезкам).

## Станции и переезды

`parseStationAxes`, `parseStationTracks`, `parseStationSwitches`, `parseCrossings` и `parseOkato`
разбирают станционные формы; `checkStations` и `checkTerritories` сверяют их между собой
и выдают замечания. Станции без путей и стрелок в экспликациях — подсказка для списка
исключений редакции, который ведёт пользователь; исключённые станции передаются
в `checkStations` и убираются из осей и экспликаций.

`importStationExports` читает полный пакет семи форм со всеми частями и передаёт
`prepareStationImport` результат разбора и основу `stationBasis`. Пакет и замечания
записываются в черновик через `PassportStationImport` одной транзакцией.
Повторный импорт заменяет прежний пакет, сохраняя ключи справочников и чужие разделы.
Замечание относится к своей форме и листу. Привязка переезда сохраняет все главные
пути направления; неизвестная координата или станция не заменяется вымышленной.
Список исключений меняется только явным вызовом `setStationExclusions`.
Подробнее — [хранилище паспорта](../../../docs/passport-storage.md#станции-переезды-и-окато).

## Вымышленные выгрузки для тестов

`src/lib/testing/passport/` собирает вымышленные выгрузки всех 17 форм паспорта (ADR-0008):
12 «веб-страничных» xls, 3 книги переездов и 2 отчёта BEx, плюс одну форму в варианте frameset.
Шапки, атрибуты ячеек, объединения и закрепления повторяют настоящие формы, а данные
придуманы: направления, станции, подразделения и ФИО взяты из `model.ts`. В данных
есть особенности, которые обязан выдержать импорт: нестандартные километры, прежние
и новые коды ПД, «Нет данных», «-1», «-----», ликвидированная станция, переезд
с неверной станцией в названии, длина отрезка, не сходящаяся с координатами.

Тесты получают файлы в памяти через `generatePassportFixtures()`; в Git фикстуры
не хранятся. `npm run fixtures [папка]` записывает их на диск (по умолчанию
`tmp/fixtures/passport`), чтобы открыть в Excel.

Правила границ — [docs/architecture.md, раздел 11](../../../docs/architecture.md) и [ADR-0001](../../../docs/adr/0001-clean-architecture-ddd.md).

```bash
npx nx test import-infrastructure
npx nx lint import-infrastructure
npx nx typecheck import-infrastructure
```
