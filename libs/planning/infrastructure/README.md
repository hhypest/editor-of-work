# planning-infrastructure

Адаптер `FilePlanStore` реализует порт `PlanStore` в main. Путь задаётся при
создании хранилища после системного диалога. Через `window.eow.planFile` доступны
открытие, сохранение, обновление снимка для минутного автосохранения, проверка
восстановления и явное принятие или отклонение автокопии. Кнопки редактора плана
и горячие клавиши относятся к #24; в этом шаге реализован и подключён файловый API.

Формат v2 хранит срез редакции, SHA-256 среза, год, гриф, работы и ручные значения,
а также исходный JSON прототипа с отчётом импорта (если проект импортирован).
Срез станции может включать `legacyLayout`: пути, их связи, ручные координаты
сетки и объекты. Это данные раскладки до появления редактора, не геометрия листа.
Линейная работа может дополнительно относиться к станции и её пути или стрелке:
это сохраняет станционные таблицы прототипа без дублирования работы.
Map записываются массивами пар, нестандартные километры — парами «км, длина».
Расчётные объёмы не сохраняются; `volume: null` означает расчёт по длине.
Строгая схема zod проверяет структуру, фабрики домена — предметные правила.
Порядок нормативов сохраняется. Реестр миграций
содержит миграцию v1 → v2: для старого файла добавляется пустое поле снимка,
остальные значения сохраняются. Закреплённые вымышленные образцы лежат в
`src/lib/testing/v1-fixture.ts` и `v2-fixture.ts`; схему v1 не изменяют.

Запись: уникальный временный файл рядом с целевым, синхронизация содержимого,
переименование. При ошибке записи или переименования основной файл остаётся
прежним. Резервные копии: `.bak`, `.2.bak` … `.5.bak`. Автокопия — `.autosave`;
она не заменяет основной файл до явного сохранения восстановленного плана.
Неизвестная новая версия и повреждённый существующий файл защищены от перезаписи.
Операции экземпляра хранилища выполняются последовательно. Гарантия рассчитана
на локальную файловую систему с атомарным переименованием в пределах тома;
устойчивость к отключению питания и поведение сетевых файловых систем не проверены.
